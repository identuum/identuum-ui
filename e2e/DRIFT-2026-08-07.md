**Failure decomposition — no failure is a UI-behaviour bug; every one is harness/state
coupling:** (a) authenticated specs log in with env-file credentials that only exist on
the owner's long-lived seeded stack — against a FRESH released backend they time out in
`beforeAll` (~180 s each; those timeouts are what stretched the run to 38 minutes);
(b) the tail cluster (site-admin-settings, upgrade-backup, verify-email) failed on
`ERR_CONNECTION_REFUSED` — the `next dev` webServer died partway through the run;
(c) the org-admin family self-skips because dynamic-fixture mode is off — and could
not be turned on: its global-setup preflight probes `/app/identuum` and an `/e2e-auth`
bind mount inside the IDP container, which is the PRE-SPLIT MONOLITH contract; the
released distroless appliance has `/app/identuum-idp` and no such mount.

## STALE-PIN: the UI's own contract spec asserts the scaffold era

`oss-contract.spec.ts` passed 5/5 against v0.3.0 — and two of those passes are
vacuous-by-shape (V2): the header still reads *"No auth, no /authorize, no /token"* —
verbatim the "old scaffold lie" that identuum-idp-oss's own
`TestOSSContract_NoScaffoldFraming` bans from its main.go — and the negative pins
(`GET /authorize MUST NOT be 200/302`, `POST /token MUST NOT be 200`) go green
against a backend that SERVES both endpoints, because a parameterless probe gets a
4xx. The spec certifies the absence of the product's core feature and passes while
the feature ships.

## The 21 residual failures, classified

1. **GENUINE UI DRIFT (feeds UI-DRIFT-API-SURFACE)** — pages that render/behave
   differently against the OSS backend than the specs expect: org-admin-smoke
   `/org-admin/users` (heading/tabs, and a filter-tab timeout), `/org-admin/settings`
   card count, `/org-admin/audit` shape; org-admin-settings + api-resources +
   service-accounts SAFE-STATE render pins. These are the UI calling org surfaces
   the OSS build serves differently or not at all (the census's CALLED-NOT-SERVED
   set — org domains/webhooks/identity-providers/invitations). Real drift, now
   visible because the pages finally load under a real session.
2. **FIXTURE-DEPTH (new residual, UI-DRIFT-FIXTURE-DEPTH)** — the `[dynamic mode
   only]` sub-tests that need SEEDED sample entities (public/confidential OAuth
   clients, an API resource, a service account) which the core envelope does not
   build. They run (dynamic mode is on) and fail on the absent entity rather than
   self-skipping. The envelope carries org + admin + user; the optional seeded
   blocks are a follow-up.
3. **HARNESS IPv6 residue (1)** — site-admin-organizations "Details link…" does an
   in-spec `apiRequestContext.post` to the UI at localhost:7104 that resolves to
   IPv6 `::1` and ECONNREFUSEs (the same localhost/IPv6 hazard the webServer probe
   documents). Env residue, not a UI defect.
4. **WebAuthn (1)** — passkey-flow "register a passkey" times out on the CDP
   virtual authenticator against the released appliance; needs its own setup.
5. **login full-flow (1)** — one assertion in the end-to-end login spec; the other
   8 login tests pass.

## What this proves

A fresh clone + Docker now reaches an authenticated green run from NOTHING: the
published v0.3.0 image on a throwaway DB, all credentials minted via the released

fixture-depth follow-up — signal the old harness could never reach because it
never authenticated against the shipped artifact at all.
