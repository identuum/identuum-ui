## The auth-transport discovery (root cause of most of the 21)

Released OSS establishes the request principal ONLY from `Authorization: Bearer`
(`mw.BearerPrincipal` never reads the `access_token` cookie; only
`/api/v1/validate` is cookie-aware). The UI forwarded cookies on every IdP call,
so admin shells rendered (validate passed) while every data panel 401'd.
Proven: the same login-issued org_admin token → 200 as Bearer, 401 as cookie on
`/clients`, `/users`, `/organizations/:id`. Owner ruling (gated on that proof):
UI-BUILDS-IT, server-side only — the BFF modules and the `/api/idp` browser
proxy lift the caller's own httpOnly `access_token` into a Bearer header on the
server→IdP hop; the token never reaches browser JS.
