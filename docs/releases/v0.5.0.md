# identuum-ui v0.5.0 — release notes

Tag: `v0.5.0` on `main`. The tag push runs `publish-ui-export.yml`, which
publishes the static export as release assets. No container image is
published for this release.

## Why this release

identuum-idp-oss `v0.8.0` embeds this release's export. A user created with
an admin-set password chooses their own at first sign-in (owner ruling
D-017); an organization admin can mark its own application first-party so
its users are not asked to consent (D-018); the audit log names who acted
and which organization a row concerns. Delta `v0.4.0..HEAD`: 25 commits
(measured at `9c8f303`) and the release commit.

## What ships

- **Release assets** (`publish-ui-export.yml`):
  - `identuum-ui-export-v0.5.0.tar.gz` — the export, a deterministic tar;
  - `identuum-ui-export-v0.5.0.json` — the `identuum-ui-vendor.v1`
    manifest: ui commit, lockfile sha256, node and pnpm versions, every
    file's sha256 and the tree digest;
  - `identuum-ui-export-v0.5.0.spdx.json` — an SPDX SBOM of the source;
  - a GitHub build-provenance attestation over the three
    (`gh attestation verify <file> -R identuum/identuum-ui`).

  The tree digest equals the manifest identuum-idp-oss `v0.8.0` embeds.

## Behaviour changes in the shared pages

- **Sign-in, "Choose a new password"** when the IdP answers
  `password_change_required` (D-017): new + confirm, then MFA when the
  organization's policy asks, else the dashboard.
- **Applications, "First-party (skip consent)"** (D-018): on the
  new-application form and a confidential application's edit form, with a
  one-line warning; the application's page shows it. A public application
  cannot be first-party (the IdP answers 400; the form says why).
- **User page, "Send invitation"** for an active, unverified user created
  with a password before D-017, where the IdP declares
  `capabilities.user_invite`; the one-time link is shown once and stays on
  the page after it re-renders.
- **Audit tables** (site admin and organization admin): the actor's type
  and role with its email, a client's client_id or a short id, and an
  Organization column. The organization admin's page lists its
  organization's rows, whoever acted.
- A pending organization's list row reads "Waiting for activation";
  assign-admin and the organization page follow D-016; audit From/To are
  the viewer's local days.

## Operator notes

- Nothing to deploy from this repository: the UI arrives inside the
  identuum-idp-oss `v0.8.0` binary and image.
- Verification at the release commit: `make verify` on `main`; see the
  release commit's report for the per-target record.
