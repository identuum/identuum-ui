# identuum-ui v0.5.3 — release notes

Tag: `v0.5.3` on `main`. The tag push runs `publish-ui-export.yml`, which
publishes the static export as release assets. No container image is
published for this release.

## Why this release

identuum-idp-oss `v0.8.2` embeds this release's export. The console no
longer logs browser console errors for answers that are not failures (a
signed-out visit to `/`, an MFA sign-in, a sign-in that must change its
password), reads an account-MFA 400 by its error code, and moves next to
16.3.7. Delta `v0.5.2..HEAD`: 8 commits (measured at `46042f7`) and the
release commit. A patch: nothing removed or renamed.

## What ships

- **Release assets** (`publish-ui-export.yml`):
  - `identuum-ui-export-v0.5.3.tar.gz` — the export, a deterministic tar;
  - `identuum-ui-export-v0.5.3.json` — the `identuum-ui-vendor.v1`
    manifest: ui commit, lockfile sha256, node and pnpm versions, every
    file's sha256 and the tree digest;
  - `identuum-ui-export-v0.5.3.spdx.json` — an SPDX SBOM of what ships (the
    production dependency closure `make export-sbom` writes, the file
    `make sbom-scan` judges);
  - a GitHub build-provenance attestation over the three
    (`gh attestation verify <file> -R identuum/identuum-ui`).

  The tree digest equals the manifest identuum-idp-oss `v0.8.2` embeds.

## Behaviour change in the shared pages

- **Expected sign-in steps are not logged as failures.** The password step,
  the password-change step, the activation and claim pending-MFA probes and
  the console's session probe and refresh send
  `X-Identuum-Login-Step-Status: 200`. An IdP that supports it
  (identuum-idp-oss `v0.8.2`) answers those expected states with 200 and the
  same body; a signed-out probe reads 200 `{"authenticated":false}` as signed
  out after still trying the refresh cookie. An IdP without the opt-in
  (identuum-idp-ce today, an older OSS) still answers 401, and every form
  reaches the same step.
- **Account MFA errors.** A 400 from recovery-code regeneration or MFA
  disable shows "MFA is not enrolled on this account." only for
  `mfa_not_enrolled`; any other 400 shows the generic error.
- **The MFA sign-in step's error is announced** (`role="alert"`), like the
  password step's.

## Dependencies

- **next 16.3.6 → 16.3.7**, the newest stable that clears pnpm's release age
  without an exclude list (16.3.8, published 2026-09-30, did not on
  2026-10-01). The shipped UI is a static export and runs no Next server.
