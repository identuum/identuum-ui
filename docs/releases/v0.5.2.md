# identuum-ui v0.5.2 — release notes

Tag: `v0.5.2` on `main`. The tag push runs `publish-ui-export.yml`, which
publishes the static export as release assets. No container image is
published for this release.

## Why this release

identuum-idp-oss `v0.8.1` embeds this release's export. It fixes GitHub
issue #1: an organization created without an admin email could not be
given an administrator from the console. It also moves next to 16.3.6
(GHSA-vcvr-r3jv-pc5j) and makes the attached SBOM describe what ships.
Delta `v0.5.0..HEAD`: 21 commits (measured at `6a0d32e`) and the notes
commit. A patch: nothing removed or renamed.

`v0.5.1` (tag on `4e4a637`) carried all of this and was never published:
its export workflow failed in `make export-sbom`, whose scratch directory
used a `mktemp` form GNU/Linux refuses. `v0.5.2` is `v0.5.1` plus that fix.

## What ships

- **Release assets** (`publish-ui-export.yml`):
  - `identuum-ui-export-v0.5.2.tar.gz` — the export, a deterministic tar;
  - `identuum-ui-export-v0.5.2.json` — the `identuum-ui-vendor.v1`
    manifest: ui commit, lockfile sha256, node and pnpm versions, every
    file's sha256 and the tree digest;
  - `identuum-ui-export-v0.5.2.spdx.json` — an SPDX SBOM of what ships:
    the production dependency closure written by `make export-sbom`
    (owner ruling D-019), the same file `make sbom-scan` judges;
  - a GitHub build-provenance attestation over the three
    (`gh attestation verify <file> -R identuum/identuum-ui`).

  The tree digest equals the manifest identuum-idp-oss `v0.8.1` embeds.

## Behaviour change in the shared pages

- **Site admin, Assign administrator** for an organization with no
  administrator and none pending (created without an admin email): the page
  now offers "Invite the first administrator" — an email, an optional name,
  and the one-time invitation shown for hand-over (mailed only when email
  delivery is configured). Before, it offered only "Re-issue activation
  token", which answered that the organization was already active. A
  pending activation and the recovery state keep the re-issue. The IdP rule
  it uses is unchanged: a site admin may invite an organization's first
  administrator, and only while it has none.

## Security

- **next 16.3.4 → 16.3.6** for GHSA-vcvr-r3jv-pc5j (critical: remote code
  execution in `next/og` `ImageResponse`, `>=16.2.0 <16.3.6`). The shipped
  UI is a static export and runs no Next server, so that server path is
  not reachable in the embedded console.

## Development artifacts

- The Next.js runner image (repo-root `Dockerfile`) is development-only
  (D-019): `publish-image.yml` is removed and no release gate judges it.
