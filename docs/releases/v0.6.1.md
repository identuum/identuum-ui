# identuum-ui v0.6.1 — release notes

Tag: `v0.6.1` on `main`. The tag push runs `publish-ui-export.yml`, which
publishes the static export as release assets. No container image is
published for this release.

## Why this release

identuum-idp-oss `v0.9.1` embeds this release's export: the sign-in fixes
for an unknown organization and a pending self-registrant. Delta
`v0.6.0..HEAD`: 16 commits (measured at `19fac27`) and the release commit.
A patch release: nothing removed or renamed.

## What ships

- **Release assets** (`publish-ui-export.yml`):
  - `identuum-ui-export-v0.6.1.tar.gz` — the export, a deterministic tar;
  - `identuum-ui-export-v0.6.1.json` — the `identuum-ui-vendor.v1`
    manifest: ui commit, lockfile sha256, node and pnpm versions, every
    file's sha256 and the tree digest;
  - `identuum-ui-export-v0.6.1.spdx.json` — an SPDX SBOM of what ships (the
    production dependency closure `make export-sbom` writes, the file
    `make sbom-scan` judges);
  - a GitHub build-provenance attestation over the three
    (`gh attestation verify <file> -R identuum/identuum-ui`).

  The tree digest equals the manifest identuum-idp-oss `v0.9.1` embeds.

## Fixed

- **Sign-in, unknown organization.** The organization lookup sends
  `X-Identuum-Login-Step-Status: 200` and reads a miss by its body, so an
  email domain that is no organization's no longer logs a failed request in
  the browser console; the sign-in falls through to the password step as
  before.
- **Sign-in, pending self-registrant.** A correct password for an account
  still waiting for approval reads "Your account is waiting for an
  administrator's approval." (it read "Login failed. Try again.").

## Console for identuum-idp-ce

The same console serves identuum-idp-ce. These follow keys identuum-idp-oss
does not send, so nothing changes on identuum-idp-oss:

- claim links and self-registration follow `capabilities.claim_links` and
  `capabilities.self_registration` (absent means served);
- organization settings show no scope-templates section and no
  self-registration wording where the IdP serves neither;
- an application reported `disabled` shows a Disabled badge and offers no
  Edit application and no secret actions (absent means enabled).
