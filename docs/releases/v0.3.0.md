# identuum-ui v0.3.0 — release notes

Tag: `v0.3.0` on `main`. The tag push runs `publish-ui-export.yml`, which
publishes the static export as release assets. No container image is
published for this release.

## Why this release

identuum-idp-oss `v0.6.0` serves the UI from its own binary on one origin:
no UI container, no Node at runtime (owner decision 2026-09-24). What it
serves is this release's static export, vendored into the binary by commit
and checked by digest. One export serves both editions; identuum-idp-ce
follows on its own track.

## What ships

- **The static export** — the shared Next pages (sign-in, first-run setup,
  account settings, the org_user dashboard, the org-admin and site-admin
  areas, activate, claim, password reset, email verification, upgrade,
  platform status) rendered through a platform layer (`export/`,
  `pnpm build:export`). The pages reach the API through the binary's `/bff`
  boundary, which lifts the HttpOnly session cookie into a Bearer on the
  server; every `/bff` request carries `X-Requested-With: identuum-ui`,
  reads included. Library code is split into size-capped chunks, every
  emitted file under 1 MiB.
- **Release assets** (`publish-ui-export.yml`, node 26.8.1, pnpm 11.3.0):
  - `identuum-ui-export-v0.3.0.tar.gz` — the export, a deterministic tar;
  - `identuum-ui-export-v0.3.0.json` — the `identuum-ui-vendor.v1`
    manifest: ui commit, lockfile sha256, node and pnpm versions, every
    file's sha256 and the tree digest;
  - `identuum-ui-export-v0.3.0.spdx.json` — an SPDX SBOM of the source;
  - a GitHub build-provenance attestation over the three
    (`gh attestation verify <file> -R identuum/identuum-ui`).

  The tree digest equals the manifest identuum-idp-oss `v0.6.0` embeds.

## Behaviour changes in the shared pages

- A session validation answered `429` is reported as unavailable, never as
  a sign-in verdict.
- Sign-out is a same-origin POST; only an unmarked `204` confirms the
  session was revoked, otherwise the page says the sign-out was local only.
- A user-detail read that fails at the IdP shows "unavailable" instead of
  "not found".

## Operator notes

- Nothing to deploy from this repository: the UI arrives inside the
  identuum-idp-oss `v0.6.0` binary. The Next server and its image are
  unchanged and are not what `v0.6.0` runs.
- Verification at the release commit: `make verify` on `main` — see the
  release commit's report for the per-target record.
