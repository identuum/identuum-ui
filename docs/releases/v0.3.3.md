# identuum-ui v0.3.3 — release notes

Tag: `v0.3.3` on `main`. The tag push runs `publish-ui-export.yml`, which
publishes the static export as release assets. No container image is
published for this release.

## Why this release

identuum-idp-oss `v0.6.3` embeds this release's export. A signed-in visitor
opening `/` now lands on their role's home, and two more pages follow what
the IdP declares it can do. Delta `v0.3.2..HEAD`: 14 commits (measured at
`36377cf`) and the release commit.

## What ships

- **Release assets** (`publish-ui-export.yml`):
  - `identuum-ui-export-v0.3.3.tar.gz` — the export, a deterministic tar;
  - `identuum-ui-export-v0.3.3.json` — the `identuum-ui-vendor.v1`
    manifest: ui commit, lockfile sha256, node and pnpm versions, every
    file's sha256 and the tree digest;
  - `identuum-ui-export-v0.3.3.spdx.json` — an SPDX SBOM of the source;
  - a GitHub build-provenance attestation over the three
    (`gh attestation verify <file> -R identuum/identuum-ui`).

  The tree digest equals the manifest identuum-idp-oss `v0.6.3` embeds.

## Behaviour changes in the shared pages

- `/` routes a signed-in site_admin to `/site-admin`, an org_admin to
  `/org-admin` and an org_user to `/dashboard`; anyone else goes to
  `/login`, as before.
- `/reset-link`, where `capabilities.admin_reset_link` is not true (every
  identuum-idp-oss), says "not available on this installation" and makes
  no call. identuum-idp-ce, which declares it true, is unchanged.
- The create-application form hides the public-client option where
  `capabilities.public_clients` is false (identuum-idp-ce). An IdP that
  does not report the key, such as identuum-idp-oss, keeps the option.

## Operator notes

- Nothing to deploy from this repository: the UI arrives inside the
  identuum-idp-oss `v0.6.3` binary.
- Verification at the release commit: `make verify` on `main` — see the
  release commit's report for the per-target record.
