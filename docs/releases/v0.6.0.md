# identuum-ui v0.6.0 — release notes

Tag: `v0.6.0` on `main`. The tag push runs `publish-ui-export.yml`, which
publishes the static export as release assets. No container image is
published for this release.

## Why this release

identuum-idp-oss `v0.9.0` embeds this release's export: the console for
organization claim links (D-022) and self-registration (D-021), and an
archived organization's page that offers only Restore. Delta
`v0.5.3..HEAD`: 29 commits (measured at `e93c626`) and the release commit.
A minor release: new pages and sections, nothing removed or renamed.

## What ships

- **Release assets** (`publish-ui-export.yml`):
  - `identuum-ui-export-v0.6.0.tar.gz` — the export, a deterministic tar;
  - `identuum-ui-export-v0.6.0.json` — the `identuum-ui-vendor.v1`
    manifest: ui commit, lockfile sha256, node and pnpm versions, every
    file's sha256 and the tree digest;
  - `identuum-ui-export-v0.6.0.spdx.json` — an SPDX SBOM of what ships (the
    production dependency closure `make export-sbom` writes, the file
    `make sbom-scan` judges);
  - a GitHub build-provenance attestation over the three
    (`gh attestation verify <file> -R identuum/identuum-ui`).

  The tree digest equals the manifest identuum-idp-oss `v0.9.0` embeds.

## New in the console

- **Claim links (D-022).** A site administrator's organization page offers
  *Issue claim link* for an active organization with no administrator: an
  optional email binds the link (mailed only where the IdP sends mail); the
  link is shown once with Copy and its expiry; issuing again warns that the
  earlier link stops working.
- **Self-registration (D-021).** Two switches, both off at first:
  - **Settings → Self-registration** (site administrator): the instance
    switch, the ceiling every organization sits under.
  - **Organization settings → Self-registration** (organization
    administrator): allow sign-up, hold new accounts for approval, require
    a verified email (disabled, with the reason, where the IdP sends no
    mail) and email domains; read-only with a note while the instance
    switch is off; the sign-up link with Copy.
  - **`/register/<org_slug>`**: closed and unknown organizations read the
    same ("Sign-up is not available"); the form checks the organization's
    stated password policy before sending and shows the IdP's refusal
    inline; every accepted sign-up reads one neutral message for the
    organization's settings, so the page never says whether an address
    already had an account.
  - **Users** (organization administrator): sign-ups waiting for approval,
    with Approve and Reject (Reject asks first).
- **Archived organizations.** The console reads the IdP's `deleted_at`, so
  an archived organization's page offers no action but Restore.

## Dependencies

- **next 16.3.7 → 16.3.8**, which clears pnpm's release age without an
  exclude list (it did not on the morning of 2026-10-01). The shipped UI is
  a static export and runs no Next server.

## Known limitations

- The sign-in page's organization lookup answers 404 for an email domain
  that is no organization's, and a pending self-registrant's refused
  sign-in answers 403; browsers log both in the console. The sign-in still
  proceeds (the lookup miss falls through to the password step).

## Operator notes

- Nothing to deploy from this repository: the UI arrives inside the
  identuum-idp-oss `v0.9.0` binary and image.
- Verification at the release commit: `make verify` on `main`; see the
  release commit's report for the per-target record.
