# identuum-ui v0.2.4 — release notes

Tag: `v0.2.4` on `main`. Published with the manual `publish-image.yml`
workflow (`version_tag: v0.2.4`, `latest_tag: false`; the workflow also
pushes a `sha-<short>` tag), under the owner's grant for this release.

## Why this release

No site administrator could restore a deleted organization from the UI.
This release fixes that and changes nothing else.

- **Site admins can restore a deleted organization** (`0145be9`) — the
  restore page read the organization with `GET /api/v1/organizations/:id`,
  which identuum-idp-oss answers with 404 for a soft-deleted organization
  by contract (its rule ORG-RESTORE-1: a deleted organization "404s on read
  yet remains restorable" through `POST /:id/restore`). The page always
  showed "Organization not found". When the read by id misses, the page now
  looks the id up among the list's deleted rows (`deleted=true`,
  `active=all`), in pages of 100, stopping at the first match and after at
  most 20 pages (2,000 deleted organizations); a miss, or a list that
  cannot be read, is still "Organization not found". The restore action is
  unchanged.
  A second cause fixed in the same commit: OSS marks a deleted row with
  `deleted_at` and sends no `deleted` boolean, so the list read every row
  as live and never offered Restore. The list now reads `deleted_at`.
  Test: `src/__tests__/org-restore-deleted-read.test.tsx` — red on
  `v0.2.3`'s code (5 of 8 failed: the deleted row read as live, the page
  showed "not found" for a deleted organization, and neither paging case
  searched the list), green with the fix.

Proven live against the published identuum-idp-oss `v0.5.0` image
(`sha256:6d7579bc…`) and a UI image built at `0145be9`, in a scratch
stack: a site administrator created an organization, deleted it, opened
it from the deleted list's Restore link, restored it, and the API read it
back as active (`GET /api/v1/organizations/:id` 404 while deleted, 200
`active=true` after the restore).

## Still limited on OSS

The organization detail, edit, delete, deactivate, reactivate and
assign-admin pages read by id too, so for a deleted organization they show
"Organization not found" on OSS. None of them is on the restore path; the
list offers only Details and Restore for a deleted row.
